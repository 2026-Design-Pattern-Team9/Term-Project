## 2026-11-20 / A · 모델과 화면 분리

### 1. 기존 문제

- `Universe`가 보드를 만들고, 마우스 입력과 메뉴를 처리하고, 다음 세대를 계산하고, 그 결과를 그렸다. 보드 전체를 한 세대 진행하려면 Swing 패널과 팝업 메뉴를 초기화해야 했다.
- 기존 클릭은 화면의 픽셀 위치를 `Neighborhood`마다 나눠 실제 셀까지 전달했다. 패턴 배치처럼 이미 행·열을 아는 코드에서도 보드를 직접 수정할 방법이 필요했다.

### 2. 변경 내용

변경 전에는 `Universe`의 틱 처리에서 `figureNextState()`와 `transition()`을 직접 호출했다. 이제 `Universe`는 `BoardModel.step()`을 호출한다. 클릭은 화면에서 행·열로 바꾼 뒤 모델에 전달한다.

#### BoardModel.java (신규)

- **보드 생성과 진행** — `createBoard()`에서 기존 64×64 보드 구조를 생성한다. `step()`은 다음 상태를 먼저 계산하고 결과를 반영한 뒤 세대 번호를 한 번 올린다. 반환값은 셀 배치가 바뀌었는지를 뜻한다.
- **보드 편집** — `isAlive(row, column)`으로 상태를 읽고, `toggleCell(row, column)`로 상태를 뒤집고, `setAlive(row, column, alive)`로 상태를 지정한다. 좌표는 왼쪽 위가 `(0, 0)`인 행·열 순서다. `clear()`는 보드를 비우고 0세대로 돌아간다.
- **상태 기록과 복원** — `snapshot()`은 배치와 세대 번호를 복사한다. `Snapshot`은 읽기 전용이고 `size()`, `generation()`, `isAlive()`로 읽을 수 있다. `restore(snapshot)`은 배치와 세대 번호를 함께 복원한다.
- **세대 완료 알림** — `addStepListener()` / `removeStepListener()`로 등록을 관리하며, 등록된 리스너에게 계산 전후 스냅샷을 계산 완료 직후 전달한다. 배치가 같은 세대도 한 번 알린다. 클릭, 초기화, 불러오기, 복원은 세대 완료 알림을 내지 않는다.
- **파일 연결** — `store(out)`은 기존 `.life` 형식으로 배치를 한 번 수집해 저장한다. `load(in)`은 읽기에 성공하면 배치를 적용하고 0세대로 시작한다. 기존 파일에는 세대 번호가 없다. 파일 선택과 스트림 닫기는 호출한 쪽에서 처리한다.

#### Universe.java (수정)

- **입력 처리** — `mousePressed()`는 픽셀 위치를 행·열로 바꿔 모델에 넘긴다. `Tick`과 `Clear`도 모델을 호출한다.
- **저장과 불러오기** — `doLoad()`와 `doStore()`에는 파일 선택과 오류 표시를 두고, 실제 보드 읽기·쓰기는 모델에 맡겼다.
- **모델 연결과 그리기** — `model()`은 메뉴와 추가 기능이 같은 모델을 쓰는 접점이다. `drawBoard()`는 모델 갱신과 그리기가 겹치지 않게 한 뒤 기존 방식으로 그린다.

[소스 파일](../../src/main/java/com/holub/life/Universe.java)

#### Cell.java와 Resident.java (수정)

- [Cell.java](../../src/main/java/com/holub/life/Cell.java)에 행·열을 받는 `isAlive()`와 `setAlive()`를 추가했다.
- [Resident.java](../../src/main/java/com/holub/life/Resident.java)에서는 `(0, 0)`에 해당하는 한 칸을 읽거나 수정한다. 직접 수정할 때 현재 상태와 다음 상태의 기준값을 함께 맞춘다. 기존 Conway 규칙은 그대로다.

#### Neighborhood.java (수정)

- **좌표 처리** — 좌표를 자식 블록의 크기로 나눠 몫으로 자식을 찾고, 나머지 좌표를 넘긴다. `setAlive()`에서 실제로 값이 바뀌면 부모 블록과 필요한 경계가 다음 세대 계산에 반영되도록 표시한다.
- **저장과 불러오기** — `load()`는 기존 좌표를 먼저 읽고 검증한 뒤 보드를 교체한다. 저장 과정에서 계산 대상 블록이 바뀌지 않으며, 예전 파일의 중복 좌표도 읽을 수 있다.

### 3. 설계 결정

- `Universe` 안에서 계속 보드 메서드를 호출하면 수정량은 적지만, 세대 진행을 테스트하거나 다른 기능에서 호출할 때 화면 코드에 의존하게 된다. 그래서 보드 조작을 `BoardModel`로 옮겼다. 강의자료는 `23 MVC.pdf` 를 참고했다.
- 그리기까지 Visitor나 별도 뷰에 옮기면 `Cell`의 화면 관련 책임을 줄일 수 있다. 이번에는 원래의 셀·블록 그리기 방식과 화면 동작을 살리기 위해 `Universe`에서 기존 그리기 경로를 사용했다. `Cell`에 남아 있는 `redraw()`와 기존 클릭 인터페이스는 이번 분리의 한계다.
- `Clock` 알림은 계산 시작 요청이다. 이력과 통계는 계산이 끝난 상태가 필요해서 `BoardModel`에 완료 알림을 뒀다. 알림은 `step()`을 부른 스레드에서 순서대로 실행된다. 통계 패널에서 Swing을 갱신할 때는 이벤트 스레드에 요청해야 한다. Observer의 변경 통지는 `3 Observer.pdf` 를 참고했다.
